# Use explicit path-specific access endpoints

Balls Server records a trusted-LAN SMB root and a full Tailscale MagicDNS SMB root as separate access endpoints tied to one stable product host identity. A client verifies, saves credentials for, and maps exactly one selected endpoint. Failure of that endpoint may make the alternate path available as an explicit owner action, but the product never silently substitutes another name, IP address, credential target, or persistent mapping. This was chosen over one guessed canonical hostname or automatic LAN/Tailscale/IP fallback because Windows name resolution, SMB authentication, Credential Manager targets, and mapped-drive persistence make those strings security and user-state boundaries rather than interchangeable routes. Endpoint drift requires re-observation and explicit re-verification; Balls Server does not create DNS aliases or rename Windows or Tailscale hosts.
