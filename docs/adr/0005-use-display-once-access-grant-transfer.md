# Use display-once access-grant transfer

The initial Connect to Files design transfers the final limited SMB credential in a setup code shown only in a transient, owner-controlled view. The setup code is treated as a bearer secret: closing or timing out the view limits exposure but does not make a copied credential expire. Rotation or revocation ends its validity. This was chosen over adding a Balls Server pairing service because a genuinely expiring one-time code would require a separately authenticated and encrypted network protocol, replay protection, rate limits, and a new attack surface before the file-sharing path has shipped. The simpler transfer keeps provisioning local-first and auditable, at the cost of requiring direct owner-to-client handling and honest disclosure that the copied code remains sensitive. A future pairing protocol requires its own threat model and milestone approval.
