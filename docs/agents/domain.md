# Domain docs

This is a single-context repository.

Before exploring domain behavior:

- read `CONTEXT.md`;
- read relevant decisions under `docs/adr/`;
- use the glossary's canonical terms in specs, tickets, tests, and code;
- surface any conflict with an ADR instead of silently overriding it.

If a required concept is missing or ambiguous, return to `/domain-modeling` through `/grill-with-docs`. Create glossary entries and ADRs only when decisions are actually resolved.
