# v0.3.0 — Setup security and architecture design

- **State:** Complete
- **Depends on:** v0.2.0

## Outcome

Every future system change, identity, consent step, failure mode, recovery action, and test boundary is defined and owner-approved before mutating code begins.

## In scope

- Exact Host Files and Connect to Files operation inventories and required privileges.
- Contract between the unelevated dashboard and narrowly scoped privileged helper.
- Change preview, explicit consent, idempotency, ownership records, partial failure, rollback, and manual recovery.
- One managed read/write folder and the rules for refusing unmanaged-share conflicts.
- One limited access identity per client Windows profile, access-grant creation/revocation, and permission-group design.
- Setup-code contents and handling, secret lifecycle, Windows Credential Manager use, lockout-safe retries, and audit/privacy rules.
- Canonical host naming plus local, Tailscale, and fallback behavior.
- Tailscale installation/sign-in handoff without handling Tailscale credentials.
- Separate default, mutating-integration, and end-to-end test suites.
- Installer, setup-helper, and repair boundaries; no overloaded executable promise.

## Out of scope

- Production system changes, shares, accounts, firewall rules, mappings, installers, or credential persistence.
