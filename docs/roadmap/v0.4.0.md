# v0.4.0 — First Working Share

- **State:** In progress
- **Depends on:** v0.3.0

## Outcome

An owner and one approved client can use the same Balls Server application to create an authenticated share and access it as a persistent Windows drive through File Explorer over either LAN or Tailscale. The application may close after setup; the host computer must remain powered on and awake for access.

## In scope

- Present clear **Host Files** and **Connect to Files** actions in one application.
- Implement the smallest complete set of privileged operations approved in v0.3.0.
- Refuse to take over an existing unmanaged share or incompatible permissions.
- Create the managed share, product-owned permission groups, and minimum private-network firewall access.
- Enforce SMB 3.0+ with SMB1 disabled, with safe handling of detected compatibility conflicts.
- Create one limited access grant without using the owner's personal Windows credentials.
- Display a copyable setup code containing one explicit LAN or Tailscale endpoint and the limited credential.
- On the client, accept the setup code, save the credential after consent, map an available persistent drive, and verify create/read/rename/delete with one temporary file.
- Record product-owned host and client changes for safe **Stop Sharing** and **Disconnect** actions.
- Distribute one portable unsigned build through a public GitHub release; one PowerShell command installs or updates application files without replacing user or product state.
- Guide Tailscale installation or sign-in as a separate user-controlled handoff when that access path is selected.

## Out of scope

- Multiple clients, automatic peer discovery, silent updates, code signing, guest or blank-password access, public TCP 445, port forwarding, and deletion of user data.
