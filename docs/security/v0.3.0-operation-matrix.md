# v0.3.0 operation completion matrix

Status: design contract for later Host Files and Connect to Files milestones. No row authorizes v0.3.0 production behavior or development-host mutation. The [ledger and recovery contract](v0.3.0-ledger-reconciliation-recovery.md) fixes the protected-state and crash semantics used by OP-03, OP-04, OP-23, OP-24, and OP-39.

Every row is an independently typed operation or explicit user action. Preview, consent, authorization, and journal prose from another row cannot fill a blank here. “Product-owned” always means the protected ledger contains the stable platform identity and expected fingerprint and the live object still matches both. Friendly names, descriptions, recovery manifests, and audit events are corroboration only.

## Completion rules

- A future mutating request has one operation ID, bounded typed data, one idempotency key, one expected ledger revision, one helper instance, and one terminal result.
- The unelevated dashboard can draft a preview, but only the one-shot elevated helper can re-observe and obtain authoritative host-mutation consent. Client-user mutations use explicit current-user consent and never invoke the helper.
- A primitive is journaled before execution and verified afterward. Cancellation is accepted before mutation and between primitives, never halfway through an unrecorded primitive.
- Automatic rollback removes only a current-transaction object whose stable identity and live fingerprint still equal the recorded postcondition. Changed, ambiguous, inaccessible, policy-managed, or unobservable state stops in Repair needed or Unknown.
- Object-specific manual recovery verifies stable identity before acting and preserves everything not named. It never deletes the managed folder or user files, rewrites a whole ACL or policy snapshot, force-disconnects open work, or adopts a matching unmanaged object.
- All audit records are local and append-oriented. They use opaque IDs, actor category, timestamps, revisions, non-secret fingerprints, bounded native codes, and result categories. Secret values, raw command or exception output, file listings, and private names or paths in default diagnostics are excluded.

## Exact recovery order when ownership proof fails

Automatic mutation stops as soon as one object lacks exact proof. The recovery view shows private names and paths only after an explicit preview; default exports remain redacted.

1. Reconcile the protected mirror and journal. If neither is authoritative, remain read-only and do not re-adopt objects.
2. For each grant, match grant ID to account SID, flags, group memberships, credential revision, and tombstone. Disable the exact account and remove only its product-group membership. Optional deletion waits for foreign-use review.
3. Match each explicitly confirmed attributable session by session ID, account SID, client, and share before closure. Never close all sessions.
4. Match the share by its exact identity, local path volume and file ID, and descriptor. Remove only the share object; never delete its directory.
5. Match each firewall rule by policy store, stable rule ID, direction, protocol, TCP port, profile, interface, and address scope. Remove only that rule; do not toggle built-in groups or GPO.
6. Match the folder by volume and file ID and the product ACE by SID, type, rights, inheritance, propagation flags, and unchanged unrelated-ACE fingerprint. Remove only that ACE; never replace the DACL or take ownership.
7. Match the product group by SID, marker, memberships, rights, and remaining dependencies before removing only that group.
8. On each affected client profile, match the drive and full UNC before non-force unmap, then match the separately recorded provider server target and qualified SAM account before credential deletion. Host cleanup cannot do this remotely.
9. Match a leftover verification file by exact path, operation ID, file identity, prefix, and known marker. Delete that one file only; never enumerate or delete user files.

Any mismatch preserves the object and directs the owner to the responsible administrator, GPO owner, Tailscale UX, or signed-in client profile. “Try setup again” is never the sole instruction.
