# v0.3.0 threat model

Status: design contract for v0.3.0. This document authorizes no production mutation.

The binding authority is the [v0.3.0 specification](../../.scratch/v0.3.0/spec.md). The research notes are supporting evidence only. The [operation matrix](v0.3.0-operation-matrix.md) applies this model to each future action, the [privileged-helper boundary](v0.3.0-privileged-helper-boundary.md) fixes the exact OP-02 authorization protocol, the [managed-resource safety contract](v0.3.0-managed-resource-safety.md) fixes the isolated OP-05 through OP-11 folder/ACE/share/firewall model, the [ledger and recovery contract](v0.3.0-ledger-reconciliation-recovery.md) fixes the isolated OP-03, OP-04, OP-23, OP-24, and OP-39 transaction model, and the [traceability ledger](v0.3.0-traceability.md) maps all specification stories and roadmap exit checks to explicit design targets.

## Trust zones

1. **Owner:** the local person who selects the managed folder, transfers setup material, and approves host mutations. Human intent is trusted only through the helper-controlled authoritative confirmation.
2. **Signed-in client user:** the Windows profile that imports a setup code and owns its Credential Manager and mapping state. It cannot authorize host administration.
3. **Unelevated dashboard:** an as-invoker presentation and planning process. It may observe, preview, import bounded bundles, and perform current-user client actions, but it is not trusted to assert privileged consent.
4. **One-shot elevated helper:** a signed on-demand process for one typed request. It authenticates its peer, re-observes state, obtains authoritative consent, journals allowed primitives, returns one bounded result, and exits. There is no standing service, scheduler, remote listener, shell, or general administration channel.
5. **Windows local security authorities:** SAM, local groups, NTFS, SMB share configuration, Windows Firewall, Server service, security policy, Credential Manager, and WNet. Product ownership must be proven with stable platform identities and exact fingerprints, not names alone.
6. **Protected host state and separate client state:** the machine-wide host ledger, mirror, append journal, audit evidence, and recovery manifest are writable only by the helper, Administrators, and SYSTEM. Current-user mapping and provider-target intent remains in a separate per-profile store and cannot become protected host ownership authority. Secrets enter neither store.
7. **Secret-transfer boundary:** the nonce-bound one-response local pipe and the transient setup-code, clipboard, and in-memory QR surfaces. The setup code is a bearer credential bundle even after its view disappears.
8. **Private SMB network:** exactly one selected trusted-LAN computer-name endpoint or full Tailscale MagicDNS endpoint. Resolution and TCP 445 reachability are observations, not authentication or authorization.
9. **Tailscale-owned zone:** installation, sign-in, naming, keys, users, peers, and tailnet policy remain outside Balls Server. The product can observe its own endpoint and hand the user to Tailscale-owned UX.
10. **Unmanaged local state:** pre-existing folders, files, accounts, groups, ACEs, shares, rules, sessions, mappings, credentials, and policy. Matching names or apparent equivalence never transfer ownership.

## Protected assets

- The managed folder, every user file beneath it, and the owner, SYSTEM, administrator, and unrelated ACEs that already protect it.
- The limited grant password, setup-code payload, Credential Manager blob, clipboard value, and transient QR representation.
- Product host ID, grant IDs, credential revisions, account and group SIDs, exact ACE tuples, share identity, firewall-rule identities, provider credential targets, mapping roots, and endpoint snapshots.
- The integrity, confidentiality, ordering, and revision of the ledger, mirror, operation journal, recovery manifest, and redacted audit trail.
- The exact plan, initiating SID and session, nonce, operation ID, plan digest, authorization deadline, helper instance, and one-response protocol cardinality.
- Private-network confinement, SMB 3.0-or-newer negotiation, SMB1-disabled state, signing protections, and the separation between LAN and Tailscale access identities.
- Current-user mappings and saved credentials that do not belong to Balls Server, active files and jobs, unmanaged Windows configuration, and all Tailscale credentials and policy.

Endpoint names, qualified account names, UNC roots, IP addresses, selected folder paths, ledger content, and audit metadata are private local data even when they are not authentication secrets. Default diagnostics redact them.

## Data flows

1. **Observation and provisional preview:** read-only probes send typed observations to the unelevated dashboard. Unknown or stale observations block the affected future mutation.
2. **Launch and peer authentication:** the dashboard creates a first-instance local pipe that rejects remote clients, launches the signed one-shot helper with `runas`, and both processes validate peer PID, token SID, session, integrity, exact protected image path, version or hash, signer, and liveness.
3. **Authoritative consent:** the helper accepts one bounded typed request, independently canonicalizes identifiers, re-observes every precondition, and computes the plan. Any difference from the provisional preview ends without mutation. A matching plan is shown in a helper-controlled TaskDialog and one Apply action consumes the two-minute authorization.
4. **Journaled host operation:** before each allowed primitive, the helper writes intent and observed pre-state to protected state. It invokes a narrow Windows API, verifies the exact postcondition, journals the result, and either continues, narrowly rolls back current-transaction objects, or records a recoverable terminal state.
5. **Display-once transfer:** grant creation or rotation leaves the account disabled. The helper generates the password and returns it once over the authenticated nonce-bound pipe. The dashboard renders one setup code containing one endpoint and the helper-observed qualified host SAM identity. A later, separately consented activation enables the matching revision.
6. **Optional disclosure surfaces:** only an explicit warned action writes the setup code to the clipboard or renders an in-memory QR. Cleanup clears the clipboard only if its current value is byte-for-byte the product-written value. Hide, close, crash, or five-minute timeout destroys the available display copy but does not expire a copied password.
7. **Initial client connection:** the unelevated client parses the setup code in transient memory, inspects exactly its selected endpoint and local collisions, then permits at most one authentication attempt for each explicit action. Access verification uses one uniquely named temporary file lifecycle.
8. **Current-user persistence:** after separate consent, Credential Manager receives the exact proven server target and WNet receives the exact selected UNC and drive letter. The provider target is stored separately from the share-qualified mapping UNC. Reconnect-profile persistence is a separate visible choice.
9. **Endpoint update:** the owner transfers a separate non-secret bundle containing one new endpoint bound to existing host ID, grant ID, and credential revision. Import changes nothing. Explicit preview, Switch, and re-verification replace only the exact product-owned provider target and mapping; the client never discovers or silently chooses another route.
10. **Repair, revoke, removal, and retention:** reconciliation classifies each object using stable identity and fingerprints. Automation changes only proven product-owned state. Host revocation and current-user client cleanup are separate. Non-secret tombstones and audit evidence are retained for 90 days after host removal and then purged.

## Attacker capabilities

The model assumes an attacker may:

- Run another unelevated process as the owner, fabricate dashboard fields, race or squat the pipe, replay a nonce, connect from the wrong user or session, or try to read a second secret response.
- Supply malformed, oversized, unknown-version, stale-revision, or semantically conflicting requests and transfer bundles.
- Rename, replace, delete, recreate, or modify a folder, reparse point, share, SID-bearing object, ACE, firewall rule, endpoint, mapping, or credential between preview, consent, mutation, and verification.
- Cause a helper or dashboard crash, timeout, cancellation, reboot, policy rejection, access denial, GPO override, open-file conflict, ledger corruption, or partial operation.
- Copy a displayed setup code, clipboard value, screenshot, or QR; inspect ordinary logs and diagnostic exports; and probe network endpoints with a stolen credential.
- Trigger repeated authentication actions in an attempt to lock an account, or induce route failure to tempt fallback to an alternate name or IP.

Required controls include strict schemas, peer authentication, exact-plan helper consent, nonces and replay rejection, stable IDs and fingerprints, handle-based path checks, write-ahead journaling, one-attempt authentication, disabled-pending grants, explicit path selection, narrow private firewall scope, redaction, and refusal on ambiguity.

## Assumptions and non-goals

- The supported host is Windows 11 Pro 24H2 or newer; the managed folder is one existing fixed-volume local NTFS directory with no unresolved reparse point in its selected tree.
- SMB1 is disabled, SMB 2/3 is enabled, minimum negotiation is SMB 3.0, signing is not weakened, and the Server service is running before host setup. These are observed administrator-managed prerequisites.
- The LAN is trusted and private, and any Tailscale path uses a private tailnet. TCP 445 is never exposed through a public profile, public address, router forwarding, external test switch, or cloud firewall.
- The product binaries and protected state locations can be ACL-protected, signed production binaries can be verified, and Windows APIs report enough stable identity for the operation being attempted. Otherwise the operation refuses.
- The owner can safeguard a bearer setup code during direct transfer and can perform named administrator or affected-client-profile recovery when automation cannot prove ownership.
- Balls Server does not claim to withstand a malicious local administrator, kernel compromise, compromised Windows security authority, compromised Tailscale platform, or an attacker who already controls the signed product binaries. Administrators can bypass ACLs and inspect memory.
- Managed-runtime zeroization is best effort. Secret lifetime and copying are minimized, but perfect erasure from process memory is not claimed.
- Tailscale reachability does not prove SMB authentication, share permission, NTFS permission, or product ownership.

## Residual risks

- A setup code copied before Hide or timeout remains usable until the grant is rotated, revoked, disabled, or expires under Windows policy. The owner must rotate or revoke after suspected disclosure.
- Screen capture, accessibility tooling, clipboard history, malware in the same user session, and memory inspection can expose a displayed secret despite short lifetime and best-effort clearing.
- TOCTOU remains possible where a Windows API accepts only a name. The helper revalidates stable directory and object identity immediately before and after each call and enters Repair needed rather than claiming atomicity.
- Provider-specific Credential Manager target behavior, firewall expression, NTFS ACE round-trip, descendant-reparse containment, and helper peer authentication require disposable-VM prototypes before their later production adapters are approved.
- External administrators or GPO can alter policy or product-owned objects after verification. Reconciliation detects observable drift; it cannot prevent policy owners or administrators from changing the machine.
- Non-force unmap, targeted session closure, or exact-object rollback can fail because resources are in use or have changed. The result remains recoverable but may require the named administrator or client profile.
- A local-account lockout or expiry can deny access. Balls Server observes effective policy and avoids retries but does not disable or rewrite that policy.
- Retained non-secret audit and tombstone data can still reveal private local metadata to an administrator; access control, redaction, local-only storage, and bounded retention reduce rather than eliminate that exposure.

## Permanent refusal invariants

<a id="no-01"></a>
### NO-01 — Global SMB and Server service

Observe SMB protocol, minimum dialect, signing, encryption, Server-service state, and policy ownership. Never enable, disable, start, reconfigure, or claim ownership of those machine-wide values. Noncompliance is an administrator handoff followed by a fresh read-only preflight.

<a id="no-02"></a>
### NO-02 — Security policy and user rights

Never change network-logon rights, deny rights, password policy, expiry policy, lockout policy, broad audit policy, or GPO. A denial, unreadable value, or policy-managed prerequisite refuses the operation and identifies the responsible administrator or GPO owner.

<a id="no-03"></a>
### NO-03 — Network and public edge

Never change network category, firewall defaults, built-in firewall groups, unmanaged rules, router or cloud policy, port forwarding, or public-edge policy. Never create Any-profile, Any-remote, public inbound TCP 445 exposure.

<a id="no-04"></a>
### NO-04 — Tailscale ownership

Never receive or store Tailscale credentials or keys, edit tailnet ACLs, install silently, sign in automatically, rename a Tailscale machine, or treat reachability as SMB authorization. Use a user-controlled handoff and re-observe only.

<a id="no-05"></a>
### NO-05 — Unmanaged object takeover

Never adopt, rename, widen, delete, or rewrite a same-name or equivalent unmanaged account, group, ACE, share, firewall rule, session, credential, or mapping. Names and descriptions are markers only; stable identity plus the ledger and exact live fingerprint are required.

<a id="no-06"></a>
### NO-06 — Folder and user data

Never take ownership of the managed folder, replace its complete DACL, recursively rewrite descendants, follow unresolved reparse points, delete the folder, delete user files, or overwrite unrelated ACEs. Repair, rollback, removal, uninstall, and test cleanup preserve the selected tree.

<a id="no-07"></a>
### NO-07 — Endpoint manufacture and fallback

Never create DNS, hosts, SMB, NetBIOS, or LLMNR aliases; rename Windows; guess a name; silently switch between LAN, Tailscale, or IP; persist an IP UNC; or use an alternate endpoint to evade a credential collision.

<a id="no-08"></a>
### NO-08 — Secret and privacy expansion

Never put a password, setup code, credential blob, QR payload, or Tailscale credential in arguments, environment variables, stdout, stderr, logs, diagnostics, ordinary configuration, ledger, crash attachments, audit events, or release artifacts. Never enable broad Windows detailed-file-share auditing, telemetry, automatic upload, or automatic export.

<a id="no-09"></a>
### NO-09 — v0.3 production mutation

v0.3.0 delivers documentation, deterministic verifiers, isolated logic prototypes, and test topology only. It adds no production helper, Windows mutation adapter, account, group, ACE, share, firewall rule, credential, mapping, installer, or Tailscale state.

<a id="no-10"></a>
### NO-10 — Unsafe uncertainty handling

Never coerce access denied, changed state, ambiguity, policy management, malformed state, or observation failure into success. Never use broad snapshot restoration, forced disconnect, closure of unrelated sessions, automatic retry, or “try again” as the only recovery instruction.

<a id="no-11"></a>
### NO-11 — Unelevated dashboard boundary

The Host Dashboard remains as-invoker and unelevated for ordinary viewing, diagnostics, provisional preview, and current-user client actions in every later milestone. It never inherits helper elevation, performs a host mutation, asserts privileged consent, or becomes a standing administrative process.

<a id="no-12"></a>
### NO-12 — Authenticated SMB only

Permanently refuse guest, anonymous, and blank-password SMB. Never enable, accept, create, preserve as product-ready, or fall back to any of those authentication modes. Every access attempt uses one enabled limited grant with a nonblank helper-generated password through SMB 3.0 or newer; observed guest, anonymous, or blank-password acceptance makes host setup and client verification Refused.

## Test boundaries

<a id="tb-01"></a>
### TB-01 — Default suite

The default suite is deterministic, offline, unelevated, and non-mutating. It needs no Tailscale, Hyper-V, administrator rights, share, account, mapping, saved credential, second computer, or network access.

<a id="tb-02"></a>
### TB-02 — Platform-neutral seams

Planner, state machine, protocol validation, ledger, reconciliation, redaction, endpoint, setup-code, endpoint-update, qualified-account, credential-target, mapping, and one-attempt policies are tested through pure or in-memory seams before Windows mutation adapters exist.

<a id="tb-03"></a>
### TB-03 — Mutating integration gate

Later mutation tests are separately discovered and opt-in. They require elevation, a disposable-VM marker, a known snapshot, a unique product-test namespace, and proof that no production identity, folder, or credential is in scope.

<a id="tb-04"></a>
### TB-04 — Two-VM isolation

LAN and optional non-production-tailnet tests use disposable Windows 11 Pro 24H2 or newer host and non-administrator client VMs on a private or internal switch. No external route, public TCP 445, real identity, or production file is allowed.

<a id="tb-05"></a>
### TB-05 — Mutation evidence and reset

Each later mutation case inventories unrelated shares, users, groups, ACEs, rules, mappings, credentials, policy, and files before and after; verifies managed-folder and required test-file survival; captures only redacted evidence; and restores or discards the snapshot.

<a id="tb-06"></a>
### TB-06 — Manual recovery verification

Failure-injection cases interrupt after every primitive and verify the exact automatic rollback precondition, Repair needed transition, object-specific recovery order, unmanaged-state preservation, and prohibition on deleting the managed folder or user files.

## Later owner acceptance

<a id="oa-01"></a>
### OA-01 — Mutation authorization gate

Only explicit owner acceptance after all v0.3.0 design tickets and review evidence may authorize later milestone work inside this envelope. Acceptance does not itself mutate Windows and does not approve an operation that is absent, wider, or less recoverable than this design.

<a id="oa-02"></a>
### OA-02 — Milestone completion gate

The default branch must contain the reviewed design and exact evidence, every exit check must pass, and the owner must approve the completion commit before the `v0.3.0` tag. Ticket 01 does not satisfy this later milestone-level decision.

## Research reconciliation

- The binding specification replaces the research sketch of a standing helper or service with one signed, one-shot elevated helper launched for a single request. The helper owns authoritative exact-plan confirmation and then exits.
- A dashboard preview is provisional usability context. It is not privileged consent, and a dashboard-supplied approval flag never authorizes mutation. The helper re-observes and presents the authoritative plan after elevation.
- The specification's five-minute setup-code display supersedes the research note's recommended 60 seconds. It limits display exposure only; the bearer password remains valid until Windows account state changes.
- Grant creation and rotation finish in Disabled pending transfer. Setup-code response or display never activates a grant. Activation is a separately previewed and confirmed operation for the exact credential revision.
- The helper-observed qualified identity is `<host-SAM-authority>\<grant-account>`. The SAM authority is independent of the Windows computer-name endpoint, MagicDNS FQDN, provider credential target, and share-qualified mapping UNC.
- The provider-supported server credential target is proved and recorded separately from the mapping UNC. The design does not assume a share-qualified target or wildcard.
- The initial credential-bearing setup code contains exactly one endpoint. A later endpoint change uses a distinct owner-transferred, non-secret bundle bound to existing host ID, grant ID, and credential revision; import alone cannot discover, authenticate, save, map, or switch.
- Global SMB and Server-service settings are observe-only prerequisites. Only separate product-owned LAN and Tailscale firewall rules are eligible for later helper mutation, and only after narrow expression and verification are proven. Tailscale credentials and policy always remain Tailscale-owned.
- The reconnect decision is two-step: credential saving begins off; only after the user chooses Save does reconnect become visibly selected by default, and it can still be cleared independently before mapping.
